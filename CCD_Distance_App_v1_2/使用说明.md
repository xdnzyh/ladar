# CCD 测距工作台 1.1

1.1 更新：连接阶段增加 250 ms 指令间隔；STOP、DEBUG 0、LASER 0、STATUS、EXPOSURE 3 超时时最多重试一次。测量 MIN 不自动重试，避免迟到回复错配。
超时提示现在包含具体指令、最近收到的消息或残片；窗口顶部可查看/复制日志，连接异常时自动打开日志窗口。
这些改进用于应对偶发丢失回复和定位问题，不能消除其他无线设备混入的数据或供电问题。

这是电脑端上位机。默认使用 11 个标定点：8～58 cm。距离基准已按“激光点到墙面 = 原 CCD 到墙面距离 − 2 cm”换算，曝光档位为 3。
它负责串口连接、单次/连续测量、分段插值、波动曲线、尺量值对照和 CSV 导出。
本版本保留静态测量，并增加了同步协议测试模式。同步模式目前显示测距设备的 session、采样序号和设备时间；电机角度需要传动 ESP32 后续发送 ANGLE/TRIG 数据后才能配对。

## 最快开始

1. 解压完整软件包，双击 CCD_Distance_App_v1_1.exe。不需要安装 Python。
2. 没连接硬件时，可勾选“演示数据（无硬件）”，点“连接 → 开启激光 → 连续测量”。演示模式不会连接任何串口，数值全部是模拟的。
3. 接真实设备时，先断开演示，取消演示勾选，按下面方式接线与连接。

## 方式一：USB 直连测距 ESP32（建议先用）

你的设备如果已在运行 CCD-CAL-1.1（INPUT=USB），就可以直接使用，不必更换固件。

1. 确认设备根目录 main.py 是测距程序，而不是电机程序。
2. 关闭 Thonny 和其他占用这个 COM 口的串口助手。
3. ESP32 通过 USB 连接电脑，同时保证 CCD 和激光模块正常供电。
4. 在上位机选中 ESP32 对应的 COM 口，点“连接”。等待数秒，出现“已连接”。
5. 点击“开启激光”，再点“测一次”或“连续测量”。

## 同步协议测试

同步协议适用于 `main_sync_v3_fixed.py`。它不会使用静态模式的逐次 `MIN` 请求，而是由上位机发送：

```text
START <session> <rate_hz> 3 fffe
```

测距 ESP32 按序号返回：

```text
PIX <session> <sample_id> <device_begin_us> <device_end_us> <ccd_x>
```

测试步骤：

1. 把 `main_sync_v3_fixed.py` 保存到测距 ESP32 的设备文件，文件名为 `main.py`。
2. 复位后确认 USB Shell 显示 `READY CCD-CAL-1.3-SYNC`。
3. 关闭 Thonny 和 SSCOM，运行上位机，勾选“同步协议”。
4. 选择测距链路串口并连接，设置同步频率，点击“开始同步扫描”。
5. 表格中的“同步序号”和“设备时间 μs”应持续变化；点击“停止同步扫描”结束。

传动 ESP32 后续可以发送 `ANGLE <session> <sample_id> <angle_deg> [trigger_id]` 或 `TRIG ...`。上位机会按 session 和 sample_id 把角度与 PIX 配对。仅有电脑接收时间不能替代这个序号配对。

如果连接超时：确保设备程序正在运行。若此前在 Thonny 点了停止，按 ESP32 的 EN/RESET 键，使设备保存的 main.py 重新运行，然后重连。
不需要重新刷 MicroPython 的 .bin 固件。

## 方式二：通过 LoRa 无线连接

电脑连接的是 USB 转 TTL + 无线接收模块；选择其 COM 口，不是电机那一路。
串口固定 115200、8 位数据位、无校验、1 位停止位，两端无线参数应匹配。
只有 INPUT=USB 的旧程序不会接收无线指令，需要先启用无线输入。

软件包内的 esp32_main.py 是配套测距程序 CCD-CAL-1.2，启动默认 INPUT=BOTH，支持 USB 与 LoRa，曝光仍为 3。

1. 用 Thonny 连接测距 ESP32，备份设备原 main.py。
2. 打开 esp32_main.py，另存为“MicroPython 设备 → main.py”。
3. 保存后重新运行或复位，确认启动版本为 CCD-CAL-1.2。
4. 关闭其他向无线模块自动发送指令的程序，在上位机选择无线接收模块的 COM 口连接。

原有接线不变：CCD TX→D16、RX→D17；LoRa TX→D5、RX→D4；激光 IN→D25。
程序只负责测距，不会启动电机。

## 看哪些数值

- 换算距离：按相邻标定点线性插值，例如坐标 910 对应 37.75 cm。
- 原始坐标：来自 CCD 的实际读数，没有自动删除离群值。
- 偏差：换算距离减去你输入的尺量距离。尺量输入可以留空，也可以在改变靶面后更新；每次测量按发出请求时的输入记录。
- 波动：最近 20 次能解析的坐标的中位数、最小/最大值、极差和样本标准差。重复性好不代表没有系统偏差。
- 距离两位小数是显示格式，不代表精度达到 0.01 cm。
- 坐标小于 855 或大于 1211 时只显示坐标和“超出标定范围”，不外推，也不把结果钳成 8 或 58 cm。

曲线默认显示最近 60 次距离，可切到原始坐标；纵轴自动缩放，误差/超范围在距离曲线上断开。
表格显示最近 200 条；内存保留最多 10000 条，导出包含全部保留记录。
切换连接会重置波动窗口和曲线，历史记录仍保留，CSV 中通过 source/port 区分。

## 为什么不一直刷英文

正常操作只看中文界面。“通信日志”页保留最近 200 行原始回复，需要排查时再看。
连接时软件依次停止旧采样、关闭调试输出、关闭激光、确认状态、发送曝光 3。
曝光显示“已发送”，因为原模块没有提供已知的曝光读回确认协议。
连续测量逐次请求和等待回复，不向设备堆积 MIN 指令。
设置的间隔是两次请求之间额外等待的时间，实际周期还包括设备和通信耗时，不是固定采样频率。
连续三次 CCD 明确报测量失败时停止连续测量；通信超时则断开，避免把迟到的回复当成下一次测量。
断开时会尝试关闭激光，连接已失效时不能保证远程关闭成功，界面会说明。

## 标定表与导出

默认表已内置；不需要手动导入 calibration.csv。可点“查看标定表”核对或导出。
更新时先断开设备，点“导入标定 CSV”；格式为：

```csv
distance_cm,ccd_x
8,1211
13,1100
18,1025
```

至少两个点，距离严格递增、坐标严格递减，允许中位数坐标带小数。
导入仅影响本次运行，重启恢复内置表；需要用新表时重新导入。历史记录保留当时的标定编号、完整标定点和换算结果。
导出使用 UTF-8 BOM，适合 Excel 打开；空距离表示超范围或失败，不是 0。
测量记录不会自动落盘，请在退出前导出。
CSV 中 source=DEMO 是模拟数据，source=HARDWARE 是串口采集数据。
pc_request_time/pc_receive_time 是电脑时间，不是 CCD 精确曝光时间，round_trip_ms 是往返耗时，不能直接用于精确旋转角度同步。

## 用于验证的建议

先停止旋转，固定设备与靶面，在 23、37、52、58 cm 等独立距离检查显示误差。
在远距离重复测量，查看是否偶发跳点，保存记录后再判断量程和可达到的精度。
保持光路、焦距、曝光和距离零点一致；换表面测试时保持靶面空间位置不变。

## 源码运行

source 文件夹内有电脑端 Python 源码，app.py 是入口；它运行在电脑 Python，不是 ESP32 MicroPython。
电脑安装 Python 3.10 或更新版本以及 Tkinter 后，在源码目录执行：

```text
python -m pip install -r requirements.txt
python app.py
```

本地完成了标定插值、越界处理、CSV、分包解析、超时、模拟 ESP32 协议、演示流程和窗口布局测试。
没有替你连接或控制真实 ESP32、CCD、电机或小车，实机验证需要按上面步骤完成。
串口实现参考：https://pyserial.readthedocs.io/en/latest/pyserial_api.html
