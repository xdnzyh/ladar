# 底盘融合上位机接入说明

## CONFIG1 接入更新（2026-09-10）

本项目已集成运行时参数；入口与步骤见 [本轮修改与调参说明](本轮修改与调参说明.md)。`navigation_config.json` 默认引用 `control/参数工具/底盘参数.json`，人工和自动毫米目标均由电脑换算 CNT。PING/MOVE/CFG 同次写入附带 32 个前导空格；连接后或手动读取/同步时核对设备参数，后续 MOVE 沿用确认状态，不再查询配置。界面可读取、重载并同步全部执行参数，提交后完整读回；重启后必须重新核对。原有动作、停止、雷达和导航状态机继续使用，自动准入仍依据实测的安全与标定数据。

## 入口与设备边界

实物程序入口为：

```text
start_hardware_navigation.bat → hardware_app.py → navigation_app.py
```

测距和旋转由两个独立 ESP32 负责，分别使用独立的 115200 串口链路，不合并控制器、不增加同步线。底盘为 Arduino UNO/AVR 工程，使用第三条独立的 9600、8N1、无流控串口链路。实际 COM 映射、无线信道、跳线与安装偏移以现场核对结果为准。

当前上位机请求雷达采样频率 100 Hz，CCD 曝光档位为 5。100 Hz 是发送给测距端的请求值，不代表硬件已达到 100 Hz；实际有效接收率、相邻 TRIG 完整圈和时间同步质量必须从现场原始数据确认。

底盘上位机适配以 `control/` 最新源码和交接资料为基准。该源码支持 MM、CNT、COMM3 PING/PONG 和严格的 ACK/DONE 报告，但交接资料没有证明车上已经烧录这一版本。首次连接时底盘能力保持 `unknown`，只有完整启动能力标记或现场版本确认后才能选择对应能力模式。

## 已接入的软件范围

- 三路串口独立配置并拒绝重复端口；雷达保持 115200，底盘固定 9600、8N1。
- 支持 MM/CNT MOVE、严格匹配 ACK/DONE、PONG、IDLE、启动能力标记、调试文本和错误回复。
- 接收解析支持分包、合包、CR/LF/CRLF、坏字节、超长行恢复、重复字段和非有限数值拒绝。
- 每个动作只发送一次 MOVE；ACK 缺失、超时或回复损坏都不会触发重发。
- MOVE 前的 COMM3 静默与 PING/PONG 握手不阻塞 Tk 主线程；任何接收字节都会重新计算静默窗口。
- STOP 使用 `!\r\nX\r\n`，优先写入并取消尚未开始写入的普通请求；停止未确认时保持运动互锁。
- 有效 DONE 只生成一次编码器执行先验；移动、制动、停稳前和旧代次扫描不写入正式地图。
- W/S/A/D/Q/E/Z/C 八方向已保存 CNT/mm 初值和来源，但默认没有现场验证范围、不确定度、速度上界与完整停止距离，自动实车动作保持锁止。
- R/F 没有旋转标定，人工与自动动作均禁止；八方向平移能力不因旋转缺失而被整体丢弃。

底盘固件没有被上位机工程自动修改、编译或烧录。离线测试与仿真不打开真实 COM，也不代表现场通信、真实位移、停车距离或实车建图已经通过。

## 文件职责

| 文件 | 作用 |
| --- | --- |
| `chassis_protocol.py` | 字节分帧，MM/CNT、ACK/DONE、PONG、IDLE、能力标记解析，MM 目标计数复算和编码器一致性检查。 |
| `chassis_controller.py` | 连接与动作代次、COMM3 握手、单在途动作、ACK/DONE、超时、STOP、通信检查和状态不明互锁。 |
| `serial_backend.py` | 分离排队与已开始写入，支持优先 STOP、部分写入反馈和跨连接会话隔离。 |
| `navigation_app.py` | 三路连接、现场配置、人工单步授权、20 次通信检查、自动准入、日志和扫描窗口控制。 |
| `runtime_config.py` / `navigation_config.json` | 统一校验能力模式、版本确认、方向范围、不确定度、速度上界、停止距离和雷达参数。 |
| `navigation_core.py` | 只规划当前可用方向，执行车体扫掠、已知自由区、膨胀障碍与单向约束，并接收一次性执行先验。 |
| `motion_safety.py` | 按规划方向检查近障，以现场速度上界和停止距离形成安全包络；缺失关键数据时拒绝自动动作。 |
| `chassis_log.py` | 记录底盘原始 RX/TX、主机墙钟与单调时间、连接代次和动作编号。 |

## 固件能力确认

最新源码的完整启动能力标记为：

```text
MECANUM UNIVERSAL V6.3 COMM READY
RX_FRAME_GUARD=1 SERIAL=9600,8N1
BRAKE_CAL=4 ALL8 SHORT-LONG
DIST_CAL=1 MM=WSADQEZC
COMM_GUARD=3 LOG=0 PING=1
```

旧版和新版可能共享第一行 V6.3 主横幅，因此仅看到主横幅不能确认 MM/PING。程序不会为获取启动横幅自动复位车辆。现场确认完整标记后，在“保存底盘现场参数”中选择：

- `mm_ping_v1`：确认支持八方向 MM 和 COMM3 PING/PONG，自动路径优先发送 MM。
- `cnt_only`：只有旧 CNT 协议证据时使用，不发送 PING，按方向系数换算一次后发送 CNT。
- `unknown`：版本或能力未确认；保持自动动作锁止。

“固件已确认”与“方向运动范围已验证”是两项独立条件。版本确认不能替代地面位移、速度、完整停车距离和安装几何测量。

## MOVE、ACK 与 DONE

MM 只适用于八方向平移：

```text
@MOVE,D,100,MM\r\n
@ACK,D,100,MM
@DONE,D,TARGET,REQ=100,UNIT=MM,TARGET_CNT=739,BRAKE=...,ENC=...,DX=...,DY=...,DR=...,DS=...,Q1=...,Q2=...,Q3=...,Q4=...
```

CNT 兼容格式为：

```text
@MOVE,D,700,CNT\r\n
@ACK,D,700,CNT
@DONE,D,TARGET,REQ=700,UNIT=CNT,BRAKE=...,ENC=...,DX=...,DY=...,DR=...,DS=...,Q1=...,Q2=...,Q3=...,Q4=...
```

请求量、请求单位、MM 内部目标计数和最终编码器进度必须分开理解：

- `REQ` 与 ACK 中的数值、单位必须与原请求完全一致。
- MM 的 `TARGET_CNT` 是固件根据该方向 CNT/mm 换算出的内部目标；CNT 的 DONE 不要求 `TARGET_CNT`。
- `BRAKE/ENC/DX/DY/DR/DS/Q1～Q4` 始终是编码器量，不能因为 `UNIT=MM` 而解释成毫米。
- `TARGET` 表示达到固件制动触发条件并完成停车流程，不保证 `ENC=REQ`，也不证明物理位移等于请求值。
- 其他终态为 `EMERGENCY`、`TIMEOUT`、`WRONG_DIRECTION`；异常终态不会自动续航。

100 mm 的固件定点换算用例为：

| MODE | W | S | A | D | Q | E | Z | C |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| TARGET_CNT | 718 | 713 | 724 | 739 | 1018 | 912 | 965 | 1019 |

这些计数只用于核对协议换算，不是 100 mm 实际位移的验收结果。八方向 CNT/mm 初值是已有数据，不应删除或伪装成未标定；但它们也不能直接标成现场验证通过。

## COMM3 发送节奏

仅 `mm_ping_v1` 使用以下动作前握手：

```text
底盘 RX 静默 500 ms
→ @PING,<8位大写十六进制nonce>
→ 收到 @PONG,<同一nonce>
→ 底盘 RX 再静默 250 ms
→ 单次 MOVE
```

旧 PONG、错误 nonce、BUSY、启动横幅重现或持续接收数据都不能当作握手成功。握手有总等待上限；持续有数据时不发送 MOVE。运行中不周期发送 PING，也不把空闲时没有主动遥测判定为失联。

界面中的“通信检查（20次）”只执行带随机 nonce 的 PING/PONG，不发送 MOVE。结果分别统计首次成功、重试成功、延迟、错误 nonce、BUSY、截断和重启；重试后的总成功率不能替代首发成功率。

## 状态机与不重发规则

| 状态 | 含义 |
| --- | --- |
| `disconnected` | 底盘串口未打开或连接已失效。 |
| `connected_waiting` | 已连接，等待空闲状态和协议能力证据。 |
| `idle` | 没有在途动作；自动动作仍须通过配置与安全准入。 |
| `waiting_silence` | 动作已登记，等待底盘 RX 静默。 |
| `waiting_pong` | 已发 PING，等待同 nonce PONG。 |
| `waiting_post_pong_silence` | PONG 已匹配，等待发送前静默。 |
| `pending_send` | MOVE 已进入发送队列，但尚未开始写入。 |
| `waiting_ack` / `waiting_done` | MOVE 已开始写入，等待匹配 ACK 或完整 DONE。 |
| `stopping` / `stopping_idle` | 已请求停止，等待动作报告或有时序约束的 IDLE 确认。 |
| `settling` | 已收到完整 DONE，等待额外停稳时间。 |
| `waiting_scan` | 自动动作已停稳，等待动作后的新完整扫描。 |
| `checking` | 正在执行不运动的通信检查。 |
| `unknown` | 动作或停止状态无法可靠确认，锁定后续动作。 |

ACK 只表示请求被接受。ACK 缺失不表示车辆没有运动，因此 MOVE 永不自动重发；完整、匹配且编码器一致性合法的 DONE 可以在缺 ACK 时结束正常动作。进入停止、超时、复位或状态不明流程后，迟到 TARGET 只能作为诊断信息，不能自动解除故障或继续导航。

同一事务的重复 ACK/DONE 不重复应用位移；停稳和等待扫描阶段的重复 DONE 不启动新动作。协议没有设备事务 ID，连续同参动作与无限迟到的旧报告无法在所有情况下完全区分；无法可靠归属时保持锁止。

## STOP 与断连边界

停止字节为：

```python
b"!\r\nX\r\n"
```

`!` 使可能存在的未完成 `@MOVE` 行无效，换行结束该行，最后的 `X` 才进入固件急停分支。若 MOVE 已完整提交到底盘，后续 STOP 不能撤回已经接受的动作。空闲 X 通常不返回 DONE，程序会在规定延迟后查询合法 IDLE；运动中的 X 通常由原动作返回 EMERGENCY DONE。

写完成回调、STOP_BEGIN、STOP_RELEASED、计划时长和串口关闭都不是外部测得的机械静止。链路可用时故障流程发送 STOP；停止未确认时，断开、重置、清图、切换模式或重新开始不能消除“可能仍在运动”的互锁。失效无线链路下，PC 不能保证机械停车，现场必须保留独立停机手段。

## 自动动作准入与执行闭环

自动动作只使用 W/S/A/D/Q/E/Z/C。主路径将规划距离从米向下量化为正整数毫米后发送 MM；CNT 兼容路径按对应 CNT/mm 换算一次。固件已经处理其制动提前量，上位机不再叠加旧请求偏置或第二层制动补偿。

每个可用方向必须分别具备：

- 明确启用状态；
- 现场验证的最小、最大可重复请求距离；
- 该方向执行不确定度；
- 可追溯的 CNT/mm 初值及来源。

全局还必须确认底盘固件能力、实际速度上界、完整停止距离和安全车体半径。任何必需字段缺失、范围冲突或单位错误都会保持自动锁止。R/F 因无旋转标定固定禁用，不补造 CNT/rad，也不把弧度不确定度复用为米。

自动闭环为：

```text
停车有效扫描 → 定位与规划 → 方向/范围/扫掠/近障检查
→ COMM3 握手及单次 MOVE → ACK/DONE 与实时安全监视
→ 应用一次编码器执行先验 → 停稳等待
→ 动作后的新相邻 TRIG 完整圈 → 雷达校正 → 下一动作
```

正式地图只接受当前会话、当前连接代次、发送边界之后且停稳后的新完整扫描。移动窗口、制动窗口、旧映射结果和旧扫描不能解除下一动作互锁。正常路径、开口探测、恢复与泊车搜索统一检查已知自由区、未知区边界、膨胀障碍、车体扫掠和单向约束。

## 配置与现场入口

在实物界面展开“串口与指令”后，可使用：

- “刷新串口”：选择测距、旋转和底盘三个互不重复的 COM。
- “读取底盘状态”：发送固件支持的状态查询；IDLE 不代表 MM/PING 已确认，也不是外部静止测量。
- “通信检查（20次）”：在确认 COMM3 能力后检查 PING/PONG，不发送 MOVE。
- “保存底盘现场参数”：保存能力模式、版本确认、八方向可用范围与不确定度、速度上界、停止距离、车体半径和雷达安装偏移。
- “现场单步授权”：由现场操作人明确授权一次 MM/CNT 短动作；人工动作同样走完整状态机。
- “紧急停止”：发送优先 STOP，并保持互锁直到停止状态得到确认。

现场参数保存后断开并重新连接设备，重新核对参数与准入原因。没有现场数据的字段应保持未确认，不能用任意默认值解锁自动导航。

具体接线、通信检查、原地雷达验证、单步动作、范围测量、安装参数和分阶段导航流程见 [底盘与雷达现场联调操作说明](底盘与雷达现场联调操作说明.md)。

## 验证层级

### 离线软件检查

在项目目录执行：

```powershell
python -m unittest discover -s tests -q
python replay_acquisition.py --input tests/fixtures/sync_replay.jsonl --config navigation_config.json --output tmp/chassis_merge_sync_replay.json
python replay_acquisition.py --input tests/fixtures/clock_sync_replay.jsonl --config navigation_config.json --output tmp/chassis_merge_clock_replay.json
```

离线测试使用假传输、固定时钟和回放夹具，不打开真实 COM。其范围包括 MM/CNT、协议损坏、COMM3 握手、不重发 MOVE、STOP 优先级、跨连接隔离、执行先验一次性应用和动作后新扫描互锁。

### 仿真验证

```powershell
python evaluate_simulation.py --config navigation_config.json --seconds 120 --seeds 20260907 20260908 20260909 --profiles IDEAL NOMINAL STRESS --output tmp/chassis_merge_simulation.json
```

仿真验证共享导航、建图、安全和观测管线，但真实底盘串口事务由假端点测试覆盖；虚拟硬件的真值只用于物理模拟和外部评分，不传入 `NavigationEngine`。仿真通过不证明车上固件版本、无线可靠性、实际位移、停车距离或地图精度。

### 现场通信与实车验收

现场必须分别保存三路端口映射、完整底盘能力标记、20 次 PING 的首发/重试明细、原始 RX/TX、相邻 TRIG 完整圈、实际采样接收率、每方向请求与实测位移、速度上界、完整停车距离、最终载荷、车体安全包络、雷达安装偏移和故障停车结果。

在这些证据完成前，只能确认软件与离线/仿真状态；不得把“现场通信通过”“真实三路同步通过”“实车建图导航通过”或“整车安全通过”标记为已完成。

## 协议固有限制

- 当前协议没有设备动作 ID、会话号、设备时间戳、CRC、停止 ACK、通信断链看门狗和全局急停抢占。
- PC 连接代次只能隔离主机旧线程和旧回调，不能给无线缓冲中的残留字节补上端到端事务 ID。
- `P` 返回的 IDLE 是底盘软件状态，不是外部测得的车轮静止。
- `ENC/DX/DY/DR/DS/Q1～Q4` 是编码器报告，不证明没有滑移或实际空间位移等于请求值。
- 真实速度、完整停车距离、DTR/RTS 复位行为、三路无线隔离、雷达安装外参和实车闭环均须现场验证。
