# RESULT1：动作一次执行，结果可重读

本次针对已经发生的回报缺字、字符损坏和行尾丢失，增加带动作编号、CRC 和停车快照的结果恢复。旧 MOVE/ACK/DONE 接口保留。新电脑端走带编号的 MOVE，正常收到结果立即结束；仅在结果损坏或缺失时查询同一个动作，不重发运动。

## 一次动作

1. 沿用原有 PING 握手及其八位十六进制编号。
2. MOVE 增加该编号和 CRC，例如 `@MOVE,W,718,CNT,1234ABCD,E06C`。收到完整行、通过 CRC、参数合法且编号与握手匹配后才执行。
3. 停车及最后编码器采样完成后，保存一份快照并自动发送 RESULT。原始 MOVE 没有附加字段时，仍回复原来的 DONE。
4. 同一次受保护 MOVE 重复到达：运动中拒绝重复启动；结果已保存时返回该结果。

CRC 使用 CRC-16/CCITT-FALSE：初值 FFFF、多项式 1021、无反射、最终不异或。范围从 `@` 到校验字段前的最后一个有效字符，不包含最后的逗号、四位校验码及 CR/LF。编号固定八位大写十六进制，CRC 固定四位大写十六进制。

## 结果与查询

完整结果字段：

```text
@RESULT,编号,方向,停止原因编号,请求值,单位,BRAKE,ENC,Q1,Q2,Q3,Q4,CRC
```

停止原因编号：0 TARGET，1 EMERGENCY，2 TIMEOUT，3 WRONG_DIRECTION。BRAKE/ENC 单位为编码器 CNT，Q1～Q4 是本次运动的四轮编码器增量。主上位机按原运动学公式计算 DX/DY/DR/DS，并核对 ENC 和请求信息。

只读查询示例：

```text
@RESULT,1234ABCD,8CE5
```

查询只读取已保存的终态，不重新采样轮子，不修改停车结果，不调用任何运动函数。请求编号仍在运动中时返回 `@RESULT,编号,B,CRC`；没有对应结果时返回 `@RESULT,编号,N,CRC`。状态回复也带 CRC。

示例（机器码仿真的 UART 实际输出，非新增实车测量）：

```text
@RESULT,1234ABCD,W,0,718,CNT,639.00,639.00,639,639,639,639,7EF0
```

快照在 RAM 中保留一份，下一次实际接受的运动或重置会清除；断电后不保留。正常上位机只允许一个在途动作，不能用此接口查询任意历史动作。新的 PING 不删除已完成快照。电脑重连或设备重启后沿用原来的未确认状态处理，不用旧结果自动恢复新任务。

## 电脑处理

新路径只接受带正确 CRC、完整字段、实际行尾且编号与当前请求匹配的 RESULT。旧的无校验 DONE 不作为新路径的成功依据。正常自动结果无需查询；没有可靠结果时，在接收静默后发只读查询，查询有次数与总时限限制。持续失败则保持未确认，不编造结果，不自动补发 MOVE。

两端共有的参数缓存和静默规则继续使用。具体恢复间隔与次数由电脑端实现控制，避免把查询无间隔堆入半双工链路。恢复不新增固定的正常起步等待。

## 固件与同步范围

本目录新增 `motion_result.h`，共八个必要源文件：`control.ino`、`utils.cpp`、`utils.h`、`calibration.h`、`runtime_config.h`、`runtime_accessors.h`、`runtime_parameters.h`、`motion_result.h`。烧录时一起复制；只复制 ino 不完整。

底层运动控制、默认速度、刹车补偿和标定系数保持原值。为让 Uno 容纳恢复功能，人工停车诊断保留目标、制动位置、最终位置、提前量、误差、位移分量、耗时和内存；机器接口所需信息独立保留。协议模式 LOG=0 时不发送周期诊断。此前尾部空行填充不再使用。

电脑源码和 exe 位于本目录参数工具；雷达主上位机实现位于项目根目录的 chassis_protocol.py、chassis_controller.py，并由 navigation_config.json 的 chassis_result_recovery 启用。该开关针对本次固件；旧固件收到扩展 MOVE 会拒绝，上位机不降级重发。

此机制处理间歇传输错误后的结果恢复。持续掉电或完全无法通信时仍无法获得可信终态，不能把离线恢复测试当作现场链路已修复。

## 空闲阶段提前握手（2026-09-10电脑端更新）

PING可以在操作者等待输入期间完成。准备好的编号只用于下一次动作，并在发送MOVE前消费；每次动作仍使用独立编号。准备成功且已满足实际接收静默后，提交动作直接写入MOVE，不再重复PING或额外等待固定静默时间。在途PING可以由新请求接管；配置、自检、复位、急停和不确定状态须清理准备状态。此项无需修改RESULT1固件，也不改变停车结果校验及只读恢复。

雷达上位机由 `chassis_idle_preflight` 开关控制，兼容缺省为false，本项目 `navigation_config.json` 已启用。非阻塞poll在确认IDLE且所需配置已核对后进行预备；读取参数和自检会等待已发出的旧PING排空。源码及验证见 `chassis_controller.py`、`runtime_config.py`、`tests/test_idle_preflight.py`。
