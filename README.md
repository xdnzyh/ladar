# TriScan 雷达控制台

当前实物入口为 `start_hardware_navigation.bat → hardware_app.py → navigation_app.py`，默认打开“仅雷达”。测距和旋转继续使用两个独立 ESP32 与两条独立 115200 串口链路，不合并控制器、不增加同步线；底盘使用 Arduino UNO/AVR 和第三条独立 9600、8N1 串口链路。

当前上位机 `START` 链请求采样频率 100 Hz，CCD 曝光档位为 5。100 Hz 是软件请求值，不是实际有效采样率或硬件能力结论；正式建图前仍须用原始 `PIX/TRIG` 记录核对相邻 TRIG 闭合、实际有效接收率和时间同步质量。旋转端协议基准为 `ROTATION_SYNC_MP_V2`；测距端同步固件、烧录条件、时间误差限制及现场检查见 [同步建图检查与烧录说明](同步建图检查与烧录说明.md)。

电脑端程序用于控制挑战实验中的旋转三角测距雷达，并可接入一条独立的底盘无线串口链路：

- 测距串口：向上层 ESP32 发送激光和 CCD 指令，接收光斑中心坐标。
- 传动串口：控制下层继电器和电机，接收光电开关的 `TRIG n` 零位信号。
- 底盘串口：以 9600 baud 接收当前麦轮固件的 `@MOVE/@ACK/@DONE/@ERR` 行协议。

程序根据 CCD 标定模型计算距离，根据相邻光电触发的时间计算旋转周期，并将每个测量点转换为平面坐标。

## 启动

双击 `start_distance_workbench.bat` 可连接当前标定固件进行静态测距。测距端换为同步固件候选后，双击 `start_hardware_navigation.bat` 进入实物“仅雷达”；双击 `start_demo.bat` 查看模拟雷达。

也可以在终端运行：

```powershell
python hardware_app.py --view radar
python simulation_app.py --view radar
```

Windows 下没有安装 `pyserial` 时，程序自动使用内置 Win32 串口后端。安装 `pyserial` 后会优先使用它：

```powershell
python -m pip install pyserial
```

## 实物接入

1. 测距和旋转两对雷达模块使用各自的 `115200` 本地串口；底盘通道使用独立信道和 `9600` 本地串口。波特率是 UART 速率，不代表无线空口吞吐率。
2. 在“仅雷达”模式至少选择测距和旋转两个不同 COM 口；需要人工底盘控制或自动导航时再选择第三个底盘 COM 口，三个 COM 口必须互不相同。
3. 默认 CCD 指令为 `@c0071#@`，返回格式为 `FF FE + 2字节`。
4. 如果设备明确使用另一种中心像素协议，才选择 `@c0081#@` 和“原始2字节”；当前 V3 基准仍以设备报告的 `fffe`/`raw2` 模式为准。
5. 点击“连接设备”。底盘能力默认保持 `unknown`；完整启动能力标记或现场版本确认完成前，不会把仅有的 V6.3 主横幅当成 MM/PING 能力证据，也不会自动复位车辆获取横幅。
6. 对已确认支持 COMM3 的底盘，每次 MOVE 前执行非阻塞握手：底盘 RX 静默 500 ms、发送带随机 nonce 的 `@PING`、收到匹配 `@PONG`、再静默 250 ms，随后只发送一次 MOVE。旧 CNT 固件选择 `cnt_only` 后不使用 PING。

## 距离标定

实物默认读取 `CCD_Distance_App_v1_2/calibration.csv`，使用与测距工作台相同的分段线性插值。表中距离单位为厘米，像素坐标必须在相邻标定点之间：

```text
distance_cm = d1 + (x1 - pixel) / (x1 - x2) * (d2 - d1)
distance_m = distance_cm / 100
```

当前表完整保存 15–100 cm 的 18 个标定点；硬件默认可信范围同步为 0.15–1.00 m。像素小于 814 或大于 1203 时不外推、不钳位，也不会被当成最大量程自由空间。`x=910` 按当前表换算为约 42.86 cm。

默认配置使用 `calibration_model=table` 和相对项目目录解析的 `calibration_file`。旧的有效 `p0/k` 配置仍作为明确的 `inverse` 兼容模型读取；显式指定的标定文件无法加载时会在启动检查中显示原因，不会静默切换到另一张表。

## 扫描与角度

开始扫描后，程序先完成双向校时，再以会话号启动测距和旋转。光电开关每触发一次代表新一圈开始。上一圈中的测量点会使用真实圈周期重新计算角度，以降低转速估计误差。旧雷达界面的“开始扫描”也复用这一同步入口，不再发送无会话的 `ROT 1`。

运行中测距有效数据超时（2 秒）、零位数据超时（10 秒）或持续校时超时后，进入额外 10 秒恢复窗口：保持雷达旋转，继续保活和双端校时重试，暂停提交建图扫描。全部超时条件消失后自动继续，并等待新的真实零位重新建立扫描；恢复窗口到期仍未恢复则暂停采集、关闭旋转和激光，需点击“开始”重新启动。界面显示恢复状态及倒计时。此处校准指时间同步及旋转零位，不改动距离标定表；紧急停止和明确的硬件故障仍立即停止。

当前雷达实际为逆时针旋转，雷达和导航配置默认使用 `clockwise=false`，界面中的“顺时针旋转”保持未勾选。零位偏移用于把光电标志物方向对准车头；如果雷达图左右镜像，切换“顺时针旋转”。

## 自主建图与导航

项目同时提供模拟程序和实物程序，两套程序共享栅格建图、激光匹配、前沿探索、A* 路径规划、避障和终点泊车逻辑。

双击启动：

```text
start_map_editor.bat          模拟地图编辑器
start_simulation.bat           隐藏地图模拟
start_hardware_navigation.bat  三串口实物程序
```

也可以从命令行启动，并直接选择“仅雷达”或“自动导航”视图：

```powershell
python simulation_app.py --view radar
python simulation_app.py --view navigation
python hardware_app.py --view radar
python hardware_app.py --view navigation
```

地图编辑器中可拖动绘制直线障碍，并设置小车起点、车头方向和参考终点。默认保存为 `simulation_map.json`，重新启动模拟程序后会自动加载；该文件不存在时才使用内置单向弯折通道。场地矩形边界自动作为外墙，画布中的每条直线作为内部障碍。导航模块不读取这些障碍坐标，只接收模拟雷达生成的距离扫描。

模拟数据源通过虚拟测距仪、零位机构和通信链路输出带设备时间戳的距离与零位观测，经重排和扫描完整性校验后生成扫描；移动停车并稳定 200 ms 后，仿真根据最近稳定转速估计相位，直接开始下一圈采样。实物路径仍要求相邻真实零位闭合。雷达周期默认按 1.5 秒配置，模拟测距频率为 100 Hz，即约 150 点/圈。自动导航界面左侧显示当前雷达扫描，右侧显示仅由扫描结果逐步建立的栅格地图。

车辆按约 20 cm × 20 cm 建模，规划使用 0.15 m 等效半径，并在障碍膨胀时增加 0.02 m 余量。单向导航会优先选择沿起点方向最远的可达前沿；拐角暂时遮住地图前沿时，程序根据雷达开口继续绕弯，并拒绝沿已经走过的通道返回。只有前向及侧向均封闭、唯一开口为来路且连续三圈复测一致时，才确认抵达另一端并泊车。

实物程序使用三个独立串口：测距、旋转机构和车辆底盘。“仅雷达”可以只打开前两个串口，也可以同时打开第三个底盘串口进行状态读取和人工标定；选择“自动导航”时必须三路均已连接。默认同步模式先双向校时，将像素经标定转换为距离，将两端设备时间转换到共同时间域并携带时间不确定度，再交给与模拟器相同的 `scan_acquisition.py` 观测接收器。会话号隔离旧数据，有限重排窗口处理乱序和重复包。旧协议兼容模式需要显式设置 `synchronized_acquisition=false`；该模式中的 `timestamped_ascii` 接受以下数据，但不具备新同步模式的校时保证：

```text
DIST,序号,设备微秒时间,距离米,中心像素
TRIG 圈号 设备微秒时间
CHASSIS,序号,设备微秒时间,左前,右前,左后,右后
```

没有设备时间戳时，程序使用电脑收到串口数据的时刻。该兼容模式只支持雷达查看，不启动自动导航；实物自动导航需使用同步观测链路。

实物界面的串口和底盘控制设置默认折叠；点击“展开串口与指令”可选择三个串口、读取底盘状态、执行 20 次通信检查并发送一次人工短动作。底盘源码支持以下两种请求：

```text
MM：  @MOVE,<W/S/A/D/Q/E/Z/C>,<正整数毫米>,MM\r\n
CNT： @MOVE,<W/S/A/D/Q/E/Z/C/R/F>,<正整数计数>,CNT\r\n
确认：@ACK,<MODE>,<原始请求值>,<MM|CNT>
完成：@DONE,<MODE>,<REASON>,REQ=...,UNIT=...,TARGET_CNT=...,BRAKE=...,ENC=...,DX=...,DY=...,DR=...,DS=...,Q1=...,Q2=...,Q3=...,Q4=...
握手：@PING,<8位大写十六进制nonce> / @PONG,<同一nonce>
错误：@ERR,BUSY / BAD_CMD / BAD_MODE / BAD_UNIT / BAD_VALUE / LINE_TOO_LONG
```

主路径在确认 `mm_ping_v1` 后优先发送 MM；兼容 `cnt_only` 时，上位机按该方向 CNT/mm 初值换算一次后发送 CNT。请求量、请求单位、MM 内部 `TARGET_CNT` 和最终 `ENC` 分开校验；`BRAKE/ENC/DX/DY/DR/DS/Q1～Q4` 始终是编码器量。100 mm 的源码换算用例为 W718、S713、A724、D739、Q1018、E912、Z965、C1019，这些数值只用于协议核对，不是实测位移。

停止使用经当前字节解析规则验证的 `!\r\nX\r\n`，先使可能存在的半行协议命令无效，再结束该行并发送 `X`；这不是断链后的机械停车保证。ACK 缺失不能作为重发依据，MOVE 在任何情况下都不会自动重发。完整匹配且编码器一致性合法的 DONE 可以在缺 ACK 时结束当前动作；DONE 缺失、异常终态、复位、断连或报告归属不明都会锁定后续动作。有效 DONE 后应用一次编码器执行先验，再经过停稳等待和动作后的新完整扫描，才允许继续建图与规划。

配置保存了 W/S/A/D/Q/E/Z/C 八方向 CNT/mm 初值及来源，但初值不等于现场验证。默认状态下底盘能力、车上固件版本、每个方向的可用范围与不确定度、实际速度上界和完整停止距离均未确认，因此自动实车 MOVE 保持锁止。现场只开放证据完整的平移方向；R/F 没有旋转标定，人工与自动入口均禁用，规划器不得生成旋转动作。人工 MM/CNT 单步也必须由现场操作人明确授权，动作后应清图或重新定位。

完整协议、状态机与证据边界见 [底盘融合上位机接入说明](底盘融合上位机接入说明.md)；从接入三路设备到分阶段开放导航的具体操作见 [底盘与雷达现场联调操作说明](底盘与雷达现场联调操作说明.md)。


## 硬件层仿真

`start_simulation.bat` 默认运行 NOMINAL。三个档位均使用同一条硬件观测处理路径：

```powershell
python simulation_app.py --view navigation --profile IDEAL
python simulation_app.py --view navigation --profile NOMINAL
python simulation_app.py --view navigation --profile STRESS
```

IDEAL 为理想器件；NOMINAL 包含距离相关噪声、慢漂移、非匀速、轮增益差异、横移滑移和通信抖动；STRESS 增加连续异常、漏零位、双触发、长尾延迟与明显停车残余运动。所有幅度与概率均为仿真假设，尚未经实物测量拟合。`--speed` 仅缩放运行节奏，不缩放设备时间、噪声或运动模型。

`navigation_config.json` 支持 `simulation_profile`、`simulation_seed`、`simulation_settle_s`（默认 0.20 秒）、`simulation_reorder_s`（默认 0.3 秒）。`simulation_parameters` 对象可覆盖 `virtual_hardware.py` 中 `SimulationParameters` 的同名字段。长度单位为米，时间为秒，角度为弧度。相同配置、地图、种子和命令序列产生可重复结果；四轮增益在整次运行内固定。

真值层独立维护车体姿态、射线原点和旋转角度。测距误差发生于距离输出，旋转纹波发生于真实运动，链路只改变到达时间与投递行为。导航依据命令进行运动预测，不接收真实位移或测距零偏。碰撞保护属于隐藏物理层。暂停冻结仿真时间并停止驱动；重新开始保留场景，重置重新建立同种子的场景。

`HardwareObservation` 是协议无关的距离/零位接口，不是串口字符串协议。当前仿真假设设备时间已映射到共同时间域，旋转仅输出零位计数和时间戳；时钟偏移、漂移估计及设备重启尚未纳入虚拟链路。正式扫描使用 `TRIG n -> TRIG n+1` 的实际周期回算该圈角度；最近最多五圈的平均周期只服务实时预览和近障方位估计。单零位仍不能观测圈内非匀速。有限重排窗口之外的迟到包被拒绝，缺失零位和过大的角度空缺会丢弃扫描。预热期间等待连续稳定周期，单独统计预热圈数。

模拟与默认实物导航共用 `HardwareObservation -> DistanceObservationReceiver -> TimedSweepBuilder -> ScanPoint -> NavigationEngine`。`EstimatedSweepBuilder` 仅保留兼容接口，不参与正式组圈；旧 `arbitrary_phase_scans` 配置不再切换建图扫描来源。仓库旧实物固件仍走像素标定协议；真实测距仪直接输出距离的最终串口格式确认后，可将解析结果接入距离观测接口。现有固件没有被改成未经确认的协议。材质、反射率、三维倾斜和平面外回波尚未建模；当前 wobble 为平面内周期角度扰动。

## 仿真评估

```powershell
python evaluate_simulation.py --seconds 120 --seeds 1 2 3 --output simulation_metrics.json
python -m unittest discover -s tests -v
```

评估程序在导航外部对照隐藏真值，按档位汇总限时到达率，并记录终点距离、位置与偏航 RMSE、已知栅格分类误差、碰撞接触次数、扫描丢弃率、预热圈数、迟到/重复/丢包数量和导航目标变更次数。到达定义为距地图参考终点不超过 0.20 米；超时不代表永久不可达。Pose RMSE 在有效扫描校正后采样，已知栅格误差不覆盖未知区域；目标变更次数不等同于所有 A* 重算次数。地图参考终点只供评估，导航仍自行探索。只有多种子且足够长的运行才能用于比较到达成功率。

## 建图与定位

扫描先过滤非有限值、低质量点和同角度重复点。匹配仅使用实际障碍回波，模拟器的最大量程射线不作为墙面约束；硬件经标定得到的 1.00 m 真实回波保留为障碍端点。地图仅接收真实测量点，不沿扫描间隙插值生成回波。

匹配使用缓存的欧氏距离场、连续 likelihood 评分和双线性采样，按粗、中、细三个尺度缩小搜索步长及评分平滑尺度。粗层默认搜索每轴 ±0.20 m、±10°；细层步长为 5 mm、0.2°。运动距离、横移量及连续失败会扩大下一圈窗口，上限为每轴 ±0.30 m、±15°。位姿正则项和最小评分收益抑制无依据的细微跳动。这是同一栅格上的多尺度搜索，不是完整的地图金字塔或 HectorSLAM 实现。

匹配置信度为启发式一致性指标，不是统计意义上的正确概率。它综合已知区域的回波吻合度、支持点数量和方向覆盖，避免把新发现区域全部当成定位错误；平行墙、重复结构仍可能存在不可观测方向。常量位于 `CorrelativeScanMatcher` 与 `NavigationEngine`，后续需用实测数据校准。

置信度低于 0.55 时保留地图及当前运动预测位姿，不写图，并返回停止命令。连续三圈失败显示“定位丢失”，后续可信扫描仍可恢复。空地图采用独立初始化：原地复测，至少三圈且障碍证据达到要求后才开始导航；初始化期间固定初始坐标系，不进行运动。

栅格使用浮点累积证据，每格每圈 hit 上限为 +2、free 上限为 -1，同圈重复点不能叠加成多次证据。quality、测距距离及扫描置信度共同缩放权重。真实回波只写入端点，沿端点之前的射线段写入自由空间；同一扫描中的 hit 优先于同格 free，不使用固定 3×3 高斯尾部，也不沿扫描间隙或插值曲线生成障碍。硬件无回波、标定外和可信量程外方向保持未知；模拟器的最大量程射线仍只更新自由空间。权重与阈值均为算法初值，不代表已标定传感器精度。

评估输出包含 `mapping_rejected_scans`、`mapping_rejection_rate`、`map_updates`、匹配退化计数和阶段耗时，与上游通信/扫描完整性丢弃率分开。原有固定种子到达测试使用模拟器实际位移作为运动预测，只检验兼容性；硬件层仿真的命令预测评估更接近接入实物时的数据条件。新旧闭环算法会选择不同路径，因此已知面积、仅已知区域的误差率和短时 RMSE 不应单独解释为全场景优劣。


## 移动节奏

仿真按累计时间安排更新，避免 Windows 等待精度导致模拟时钟逐步落后。正常倍率保持约 1 秒现实时间对应 1 秒仿真时间。

同一前沿目标存在多条可行路线时，8 方向路径代价会计入转向角，优先保留较长的连续直线段；连续同向栅格在显示和执行前合并为直线段，拐角不会被跨越。`path_turn_penalty` 默认 0.75，数值越大越偏向少转折，但仍只在已知自由栅格和膨胀障碍之外选路。

定位匹配分数达到 0.75 且直线路径全部位于已知自由格、避开膨胀障碍并通过最新雷达车体扫掠检查时，单次轴向移动最多为 0.20 米，不提高底盘速度。路径方向接近 45° 时允许发送固定比例的前后加左右平移，斜向速度约 0.11 m/s、单次距离不超过 0.10 米；探测开口时再收紧到 0.08 米。斜向移动后下一圈匹配会额外扩大搜索窗口，接受扫描校正后才清除这部分不确定度，以吸收麦轮实际位移偏差。未知区域、障碍附近和较低匹配分数仍使用短段；开口探测保持谨慎的小步行为。停车稳定等待和完整扫描校验继续执行，因此移动仍是分段式；仿真不会额外等待下一次零位。


模拟器和同步实物移动期间持续接收零位与距离观测，但不把移动中的扫描交给建图。仿真在停车基础等待结束后，根据最近稳定转速估计相位并从下一条距离观测开始累计一圈；同步实物仍从下一次真实零位开始收集到相邻下一次零位，使用实际周期统一回算角度。首次启动与角度基准失效后需重新积累稳定周期。`hardware_settle_s=0.2` 和 `simulation_settle_s=0.2` 均为可调整初值，不是实测停车时间。

同步采集沿用配套固件的 `START`、`PIX`、`ROT`、`TRIG`、`SYNC` 和 `PING`，不在每次移动或每 30 秒重启旋转。`sync_scan_duration_s` 不再控制会话寿命。运行中按 `sync_interval_s=0.5` 秒持续校时，按 `keepalive_interval_s=5` 秒保活；已生成观测的时间和不确定度保持不变。连续 `sync_max_age_s=8` 秒没有有效校时，或新旧校时区间与漂移预算不相容时停止采集并通知导航停车。


模拟和默认同步实物雷达图约每 50 ms 刷新，逐点显示最近一个旋转周期的回波及同一回波对象的距离、方位，移动期间也持续更新，不等待完整一圈。预览使用经重排的设备观测和估计角度，因此仍有通信与重排延迟；首次启动需先获得可用转速估计。实物相邻真实零位闭合后，即使回波只覆盖部分方向，也会把可信回波提交到固定姿态局部地图；完整圈仍单独保留给自动导航，预览刷新不会触发导航运动。

实物观测重排等待由 `observation_reorder_s` 配置，默认 0.3 秒；超过窗口的迟到数据不参与组帧。该值须覆盖实测无线链路延迟。观测携带距离（米）、公共时间域时间（秒）、源与序号、状态、时间不确定度及原始像素。无回波与超量程不能混同；无效像素不转换成最大量程自由空间。


## 扫描质量与连续校时

单点采集区间、时钟误差或角度位置误差超限，只剔除该点；整圈最后统一检查至少 12 个有效点及角度覆盖。普通测距序号缺失不重置组圈；零位序号不连续、时间倒退、零位超时、严重周期异常会使角度基准失效。无效测距包不会被替代为虚构回波。

最大允许缺口为 `min(scan_gap_hard_limit_deg, max(max_scan_gap_deg, scan_gap_factor * median_gap))`，默认值分别为 45°、25°、2.5。约 120 点/圈时正常间隔约 3°，允许孤立缺点形成约 6° 的缺口及少量抖动，但连续缺两点的约 9° 缺口仍会拒绝；硬上限防止稀疏数据或参数组合容许大面积缺测。

`clock_drift_bound_ppm=500`、`max_timing_position_error_m=0.04` 保持不变。单端 30 秒无更新可额外累积 15 ms 的误差；现在通过频繁双向校时，将上一模型按漂移上界扩展后与新往返时间得到的偏移区间求交，以交集中心和半宽更新模型。时间不确定度按样本发生时间计算，不把无线排队时间误当设备漂移时间；双向时延不对称仍包含在误差区间内，不以对称时延假设消除它。链路本身太慢或不对称时，4 cm 预算仍可能拒绝远距离点；持续校时不能凭空得到更高精度。

## 移动时近障停车

`motion_safety.py` 独立接收实时距离观测，不等待整圈或 SLAM。沿前进、后退、横移方向出现近障时触发现有 STOP；旋转时检查周边，近回波方位不可信时保守停车。过期数据不会重置测距存活时间，运动中长期无有效测距也停车。此逻辑仍运行在 PC 上，受采样覆盖、无线通信与 PC 调度影响，不替代底盘本地保护。

| 参数 | 默认值 | 含义 |
| --- | --- | --- |
| `safety_clearance_m` | 0.12 | 车体半径外近障余量，须按实测制动调整 |
| `safety_max_observation_age_s` | 0.5 | 可用于安全检测的最大观测年龄 |
| `safety_blind_timeout_s` | 0.75 | 运动期间有效测距更新中断的停车门限 |
| `safety_max_angle_error_deg` | 15 | 近回波超过该方位误差时保守停车 |
| `hardware_settle_s` | 0.2 | STOP 发出后基础等待，尚无实际停稳反馈 |

底盘控制端已按 `car control_fixed/` 的最新交接源码接入上位机；源码具备 MM、CNT 和 COMM3 PING/PONG，但车上是否已烧录该版本仍待现场确认。底盘没有动作 ID、设备时间戳、CRC、通信看门狗或全局急停抢占；ACK/DONE 超时、错误回复、重复或迟到报告、复位和断连都会锁定自动控制，不会自动重发 MOVE。PC 停止字节不能保证失效无线链路下的机械停车，实车仍需现场独立停机手段、速度/制动测量和逐项验收。

底盘接入的协议、状态机、离线测试和装车步骤见 [底盘融合上位机接入说明](底盘融合上位机接入说明.md)。

## 测距协议适配

`measurement_protocol.py` 负责解析现有 PIX/TRIG 串口格式、标定距离与规范化时间。`DeviceObservation.normalize()` 将设备域观测转成 `HardwareObservation`；已具有共同时间域的距离数据也可直接构造 `HardwareObservation(source="range", distance=...)` 送入接收器。未来真实距离协议只需补充对应解析适配器，不修改组圈或 `NavigationEngine`。设备时间、到达时间、距离有效性和不确定度必须分开提供。

验证命令：`python -m unittest discover -s tests -v`。回归覆盖孤立异常点、连续缺测、真实圈周期、零位故障、运动扫描隔离、双时钟持续漂移、90 秒连续采集、不对称校时、过期校时、安全层方向判断和协议标准化。软件回放不等于实际无线时延、轮速、停车距离或建图精度验收。
