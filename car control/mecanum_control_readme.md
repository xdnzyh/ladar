# 麦克纳姆底盘控制端 README

## 1. 本文档用途

本文档用于同步底盘控制端当前已经确定的接口、运动定义、编码器数据含义、控制能力和后续标定约定。

另一侧控制程序 / AI 可以直接以本文档为底盘侧事实来源，不需要从源码反推以下内容。

当前总体工作方式预计为：

```text
上层感知/雷达测量
        ↓
决定一次短距离移动
        ↓
发送移动命令给底盘
        ↓
底盘 ACK
        ↓
底盘执行闭环运动
        ↓
底盘停车
        ↓
底盘返回编码器执行结果
        ↓
上层重新测量真实位置
        ↓
决定下一次修正
```

设计重点是“短距离动作 + 重新观测”，不是依靠轮编码器长期进行绝对位置推算。

实际任务中，单次平移通常预计不超过约 20 cm。

## 2. 当前程序版本

当前通信版：

```text
MECANUM UNIVERSAL V6.3 COMM
```

主要能力：

- 四轮麦克纳姆底盘闭环运动
- 前进 / 后退
- 左右侧移
- 四个斜向
- 顺时针 / 逆时针原地旋转
- 保留电脑串口单键控制
- 支持另一控制端通过串口发送完整移动指令
- 收到命令后先返回 ACK
- 动作结束后返回 DONE 和编码器执行结果

当前串口波特率：

```text
9600 baud
```

## 3. 坐标和方向约定

从小车上方向下看：

```text
                 FRONT

          M2                M1
       左前轮             右前轮


          M3                M4
       左后轮             右后轮

                 REAR
```

定义：

```text
+X = 向前
-X = 向后

+Y = 向左
-Y = 向右

+R = 顺时针旋转
-R = 逆时针旋转
```

这里的 `X / Y / R` 首先是由轮编码器根据麦克纳姆理想运动学计算出的模式量。

尤其需要注意：

> 编码器只能测量轮子转动，不能直接测量轮胎或麦克纳姆滚子是否相对地面发生滑动。

因此 `X / Y / R` 不应无条件理解为真实世界中的绝对位置和绝对姿态。

## 5. 编码器

编码器接线：

```text
E1 / M1 → Arduino D8 / D9
E2 / M2 → Arduino D6 / D7
E3 / M3 → Arduino D2 / D3
E4 / M4 → Arduino D4 / D5
```

使用 AB 正交编码。

实测确认：

```text
COUNTS_PER_REV ≈ 1440 count / 输出轮一圈
```

10 圈手动测试约得到：

```text
14400 count
```

当前内部已经统一编码器逻辑方向：

```text
q1 = -rawM1
q2 = +rawM2
q3 = -rawM3
q4 = +rawM4
```

因此上层不应再对单轮编码器自行翻转正负号。

## 6. 编码器运动学定义

当前位置模式：

```text
X = (q1 + q2 + q3 + q4) / 4
Y = (q1 - q2 + q3 - q4) / 4
R = (-q1 + q2 + q3 - q4) / 4
S = (q1 + q2 - q3 - q4) / 4
```

其中：

```text
X = 前后模式
Y = 左右侧移模式
R = 旋转模式
S = 前后轴内部不一致模式，主要用于控制/诊断
```

对应轮速：

```text
Vx = (v1 + v2 + v3 + v4) / 4
Vy = (v1 - v2 + v3 - v4) / 4
Vr = (-v1 + v2 + v3 - v4) / 4
Vs = (v1 + v2 - v3 - v4) / 4
```

## 8. 当前动作进度 CNT 的严格定义

通信协议当前使用的距离单位为：

```text
CNT
```

这里的 CNT 不是简单等于某一个 `X / Y / R` 数值。

程序针对当前运动，将所有主动轮的编码器位移投影到运动方向，然后取平均：

```text
progress =
    average(
        baseDir[i] × (qi - qi_start)
    )

仅统计 baseDir != 0 的主动轮
```

因此：

```text
W: progress ≈ +X
S: progress ≈ -X
A: progress ≈ +Y
D: progress ≈ -Y
R: progress = +R
F: progress = -R
```

但对于斜移，例如 Q：

```text
M1 +
M3 +
```

因此：

```text
progress = (Δq1 + Δq3) / 2
```

而理想情况下：

```text
X ≈ progress / 2
Y ≈ progress / 2
```

所以：

> 对斜移，通信中的 `ENC` / `CNT` 不应直接和 `DX` 或 `DY` 数值比较。

例如目前一次 Q 运动：

```text
ENC ≈ 1300 CNT
DX ≈ 650
DY ≈ 650
```

这是正常的定义结果。

## 9. 当前外部通信协议

### 9.1 发送移动命令

格式：

```text
@MOVE,<MODE>,<VALUE>,CNT
```

例如：

```text
@MOVE,W,700,CNT
@MOVE,D,1400,CNT
@MOVE,Q,1200,CNT
@MOVE,R,500,CNT
```

### 9.2 行结束

一条协议命令必须以换行结束。

支持：

```text
LF
CR
CRLF
```

建议正常发送：

```text
@MOVE,D,1400,CNT\r\n
```

### 9.3 命令大小写

协议前缀必须使用：

```text
@MOVE,
```

MODE 可以使用大写或小写，例如 `D` / `d`。

单位当前应发送：

```text
CNT
```

不要发送小写 `cnt`。

## 10. ACK

当底盘成功解析并接受命令后，在电机启动前返回：

```text
@ACK,<MODE>,<VALUE>,CNT
```

例如：

```text
@ACK,D,1400,CNT
```

ACK 的准确含义是：

> 命令已经通过语法检查并被底盘接受，即将开始执行。

ACK 不表示运动已经完成。

---

## 11. DONE

运动完全结束、制动完成、最终编码器读取完成之后，返回：

```text
@DONE,...
```

示例：

```text
@DONE,D,TARGET,REQ=1400,UNIT=CNT,BRAKE=1402.50,ENC=1481.75,DX=-28.75,DY=-1481.75,DR=-37.25,DS=3.25,Q1=-1470,Q2=1419,Q3=-1551,Q4=1487
```

`@DONE` 被设计为该动作最后一条机器协议消息。

因此另一端推荐：

```text
发送 MOVE
→ 等 ACK
→ 等 DONE
→ 再发送下一条 MOVE
```

---

## 12. DONE 字段含义

### MODE

本次实际执行的运动模式。

### 状态

可能为：

```text
TARGET
EMERGENCY
TIMEOUT
WRONG_DIRECTION
```

- `TARGET`：正常达到编码器目标。
- `EMERGENCY`：动作被急停。
- `TIMEOUT`：规定时间内没有完成目标。
- `WRONG_DIRECTION`：编码器检测到运动明显沿目标反方向发展。

### REQ

上层请求的目标 CNT，例如：

```text
REQ=1400
```

### UNIT

当前固定：

```text
UNIT=CNT
```

### BRAKE

开始执行主动制动时的运动进度。

### ENC

制动完成后最终编码器运动进度。

这是当前最适合作为“底盘编码器认为本次最终实际执行了多少”的字段。

> ENC 是编码器运动量，不保证等于真实世界物理位移。

### DX / DY / DR / DS

本次动作结束后的编码器运动学分量，全部相对于本动作开始位置，而不是上电以来的累计值。

### Q1~Q4

四个轮子的本次相对逻辑编码器变化，用于更细的运动质量判断或离线分析。

## 13. 错误回复

可能返回：

```text
@ERR,BUSY
@ERR,BAD_CMD
@ERR,BAD_MODE
@ERR,BAD_UNIT
@ERR,BAD_VALUE
@ERR,LINE_TOO_LONG
```

### BUSY

当前正在执行另一动作。另一端不要并发发送移动命令。

推荐严格：

```text
MOVE
→ ACK
→ DONE
→ 下一条 MOVE
```

### BAD_MODE

MODE 不属于：

```text
W S A D Q E Z C R F
```

### BAD_UNIT

当前只支持 `CNT`。

### BAD_VALUE

目标值非法，例如 0、负数或非整数。

## 17. 当前已经验证的运动能力

### 前进 / 后退

当前短距离运动表现正常。

在实际任务关注的约 20 cm 内，没有观察到明显异常。

当前前后运动控制参数已经基本冻结。

### 左右侧移

纯侧移对麦克纳姆轮的地面作用要求明显高于前后运动。

当前已经为侧移使用独立的高驱动力 profile。

实测 A / D 已经能够进行比较稳定、连续的侧向运动。

短距离运动仍可能存在少量航向误差，因此不要将编码器侧移结果视作最终真实空间位置。

### 斜移

斜移只主动驱动两个轮。

原有较低驱动力不足，目前已经改为独立高驱动力 profile。

Q（左前）已经进行多次实测，能够稳定连续运动。

典型实测：

```text
PWM ≈ 117~122
主动轮速度 ≈ 24~27 count / 20 ms
非主动轮 PWM = 0
```

多次 Q 结果中：

```text
DX ≈ DY
```

符合左前斜移运动学预期。

E / Z / C 使用相同控制结构和同类参数，但仍应视为需要实际确认的方向。

### 旋转

R / F 的控制结构已经存在。

当前旋转 profile 仍为早期参数，尚未完成专项实车调节和角度标定。

因此另一端当前不要假设：

```text
500 CNT = 某个已经确定的角度
```

## 19. 为什么侧移 / 斜移 PWM 上限比前后高

`PWM MAX = 180` 表示允许控制器在需要时使用更大的驱动力，不表示电机始终运行在 180。

例如已经正常工作的侧移中，实际常见输出仍然大约：

```text
120~140
```

斜移正常运行时也可只有约 120。

提高上限的主要作用是：

```text
起步或高负载
→ 给控制器更大的扭矩余量

轮子已经正常运动
→ 输出自然下降
```

因此另一端无需根据不同 PWM profile 改变协议。

## 20. 当前闭环控制结构

控制周期：

```text
20 ms
50 Hz
```

轮速低通：

```text
alpha = 0.35
```

四轮使用 differential wheel PI：

```text
KP = 0.80
KI = 0.30
I output limit = 10
```

这个积分主要用于调整轮间相对差异，而不是无限提高四轮公共输出。

## 21. 平移航向控制

前后、侧移和斜移过程中使用：

```text
Vr + 有限时间记忆 rMem
```

进行短时间航向稳定。

当前主要参数：

```text
KR_D = 1.25
R_MEM_LEAK = 0.985
K_RMEM = 0.020
R_MEM_LIMIT = 75
MAX_RMEM_CORRECTION = 1.5
MAX_R_CORRECTION = 5
```

每一个独立移动动作开始时，`rMem` 会重新清零。

---

## 22. 不要把累计 R 当成真实绝对航向

历史实验已经确认：

> 编码器运动学中的累计 `R` 在平移过程中不能可靠代表真实车头绝对角度。

因此当前控制中 `Rglobal` 不用于平移过程的绝对航向闭环。

短时间旋转趋势 `Vr` 与真实当前转向趋势更有相关性，因此平移控制主要使用 `Vr + rMem`。

---

## 23. 侧移的根本观测限制

纯侧移过程中，麦克纳姆轮高度依赖滚子、地面摩擦、实际载荷和接触状态。

假设编码器显示：

```text
Y = 1000
```

不能保证真实车体一定横向移动了固定的毫米数。

可能存在：

```text
轮子确实转了
但部分转动消耗在滑移中
```

编码器无法通过自身判断这一点。

因此：

> 对侧移，编码器适合用于动作内部闭环和执行状态反馈，但最终真实位置应由雷达/外部感知重新确认。

## 25. 前后方向已有较可靠的初步比例

轮径约：

```text
65 mm
```

轮周约：

```text
204.2 mm
```

编码器：

```text
1440 count / rev
```

理论得到：

```text
1 count ≈ 0.1418 mm
约 7.05 count / mm
```

实测曾有：

```text
约 7200 count ≈ 约 102 cm
```

与理论值非常接近。

因此在正式精标定以前，前后可以暂时用以下数量级作为参考：

```text
5 cm  ≈ 353 CNT
10 cm ≈ 706 CNT
20 cm ≈ 1410 CNT
```

但最终仍建议分别实测：

```text
W 的 CNT/mm
S 的 CNT/mm
```

而不是直接永远使用理论轮径。

---

## 26. 侧移不能直接套用前后 CNT/mm

虽然理想麦克纳姆运动学可以从轮转动推算 Y，但真实侧移存在明显滑移因素。

因此 A / D 必须分别通过真实地面位移进行标定。

不要直接使用：

```text
7.05 CNT/mm
```

作为真实横移系数。

---

## 27. 斜移也必须单独理解 CNT

斜移中的 `ENC` 是两个主动轮沿运动方向编码器增量的平均值。

例如 Q：

```text
ENC = (Δq1 + Δq3) / 2
```

理想编码器运动学：

```text
DX ≈ ENC / 2
DY ≈ ENC / 2
```

因此斜移的 CNT/mm 数值不能直接照搬前后。

后续建议分别标定：

```text
Q CNT/mm
E CNT/mm
Z CNT/mm
C CNT/mm
```

如果实测证明对称性足够好，再决定是否合并系数。

---

## 28. 旋转需要 CNT/degree 标定

旋转时：

```text
R MODE → ENC ≈ +R
F MODE → ENC ≈ -R 的绝对运动量
```

但当前还没有可靠的：

```text
CNT / degree
```

系数。

后续需要分别测量：

```text
CW CNT/degree
CCW CNT/degree
```

然后才能把协议扩展到角度单位。

---

## 29. 制动超调

当前底盘不是在达到目标 CNT 后立即无惯性静止。

过程是：

```text
达到控制目标
→ 开始制动
→ 约 300 ms 后释放
→ 读取最终编码器位置
```

因此协议同时返回：

```text
BRAKE
ENC
```

通常：

```text
ENC > BRAKE
```

例如斜移 Q 的历史数据：

```text
BRAKE 1212.5
ENC   1324.0

BRAKE 1228.0
ENC   1338.0

BRAKE 1212.0
ENC   1289.5
```

因此以后进行精确距离控制时，需要考虑：

```text
目标物理距离
→ 目标最终 CNT
→ 根据运动类型和速度预测制动超调
→ 提前开始制动
```

而不是简单等到最终目标 CNT 才刹车。

## 30. 推荐后续距离标定方式

正式标定建议分别记录：

```text
请求 CNT
BRAKE
最终 ENC
真实物理位移
```

每个运动方向至少进行多次测试。

需要建立：

```text
W：CNT/mm
S：CNT/mm
A：CNT/mm
D：CNT/mm
Q：CNT/mm
E：CNT/mm
Z：CNT/mm
C：CNT/mm
R：CNT/degree
F：CNT/degree
```

同时记录：

```text
最终超调 ENC - BRAKE
```

这样后续可以同时完成：

1. 物理单位 → CNT
2. 制动提前量

## 31. 后续协议预计如何扩展

当前：

```text
@MOVE,D,1400,CNT
```

完成距离标定后，可以在不改变整体通信流程的情况下扩展为：

```text
@MOVE,D,120,MM
```

表示向右移动 120 mm。

旋转：

```text
@MOVE,R,30,DEG
```

表示顺时针 30°。

届时底盘内部负责：

```text
MM / DEG
→ 对应模式的目标 CNT
→ 执行现有闭环控制
```

ACK / DONE 整体流程无需重设计。

## 32. 推荐上层控制策略

不推荐：

```text
雷达只测一次
→ 让底盘依赖编码器连续移动很长距离
→ 认为最终位置一定正确
```

推荐：

```text
雷达测量
→ 计算一个短距离移动
→ 发送 MOVE
→ 等待 ACK
→ 等待 DONE
→ 读取 ENC 作为底盘执行记录
→ 雷达重新测量真实位置
→ 根据残余误差再次移动
```

尤其对于侧移，这种闭环结构能够自然处理编码器无法观测的滑移。

## 33. 上层当前最重要的几条约束

另一控制端当前请遵循：

1. 一次只发送一条 MOVE。
2. 等当前动作 `@DONE` 后再发送下一条。
3. 当前只发送 `CNT`。
4. 不要把 `ENC` 直接解释成毫米。
5. 不要把 `DX/DY/DR` 当成外部传感器测得的真实 pose。
6. 对侧移尤其不要完全依赖编码器推算真实横向位置。
7. 当前实际使用重点是短距离动作，典型上限约 20 cm。
8. 最终真实空间误差由雷达/外部感知闭环修正。

## 35. 给后续 AI / 开发者的原则

如果继续修改底盘控制，请保留以下已经得到实车支持的结论：

- 不要因为前后 PWM 90~120 工作良好，就强制其他运动也使用同一动力范围。
- 侧移和斜移需要明显更大的驱动力权限。
- `MAX_PWM=180` 是控制余量，不代表实际持续以 180 输出。
- 不要使用累计 `Rglobal` 作为平移时的真实绝对航向。
- 不要假设轮编码器可以检测麦克纳姆侧向滑移。
- 不要用一次测试结果对某一电机建立永久静态补偿。
- 理论静止的斜移轮目前保持 release。
- 优先保证短距离动作稳定和可重复，而不是追求长距离纯编码器航位推算。
- 底盘编码器和雷达应当互补，而不是互相替代。
